# Hazaism — 端材教

**▶ アプリを開く: https://aho-wono.github.io/hazaism/**

レーザーカッターで出た板の端材を使い切るためのアプリです。ブラウザで開くだけで使えます（インストール不要）。
名前は「端材教（hazai＋-ism）」から。端材を一枚も無駄にしない、という教えです。
格子マットの上で撮った写真から端材の輪郭を寸法つきで起こし、部材の DXF を敷き詰めて、加工機に渡す DXF を作ります。

1. 端材を 1 マス 10 mm の格子マットに置いて写真を撮る（スマホで撮って、そのままパソコンへ送れます）
2. 輪郭を確認して、必要なら直す
3. 部材の DXF と個数を登録する
4. 自動で敷き詰める
5. 原点と向きを決めて DXF を保存する

## 使う前に

- **パソコンの Chrome か Edge を勧めます。** Firefox や Safari でも動きますが、DXF の保存先を選べません（「ダウンロード」フォルダーに入ります）。
- **最初に開いたときは、読み込みに 1 分ほどかかります。** 計算に使う Python とライブラリ（数十 MB）をブラウザに読み込むためです。
  2 回目からはブラウザに残っているので速く開けます（ネットにつながっていなくても開けます）。
- **写真や図面は外へ送られません。** 計算はすべて、開いたパソコンのブラウザの中で行います。
  スマホから送るときも、写真はスマホからパソコンへ直接届きます（[下](#スマホで撮って送る)を参照）。
- 作業は自動でブラウザに保存されます。ページを閉じても、次に開いたときに続きから始まります。
  別のブラウザや別のパソコンには引き継がれません。
- メモリを多く使います（敷き詰めの計算中は 1〜2 GB）。ほかの重いページは閉じておくと安定します。

## 使い方

右上の「最初から」で写真と輪郭を消して次の端材に進めます（登録した部材を残すか消すかを選べます）。

### 1 写真

- マットは **1 マス 10 mm**（5 本ごとに太線）を前提にしています。
- 写真はファイル選択、ドラッグ＆ドロップ、貼り付け（Ctrl+V）で読み込めます。
  スマホで撮った写真は、「スマホから送る」で直接送れます（次の節）。
- 読み込むと、見つけた格子が写真に重ねて表示されます。線が写真の格子に重なっていれば正常です。
- 格子が自動で見つからないときは「格子を手動で合わせる」で、交点 4 つとマス数を指定します。
- HEIC の写真は、ブラウザが開ければそのまま読めます。読めないと言われたら JPEG に変換してください。

#### スマホで撮って送る

スマホで撮った写真を、パソコンの Hazaism へ直接送れます。届くと自動で解析が始まり、結果（格子が見つかったか、板が何枚か、
撮り直したほうがよいか）がスマホにも出ます。iPhone でも Android でも使えます。アプリを入れる必要はありません。

初回だけ:

1. パソコンの Hazaism で、右上の「スマホ」（または写真の画面の「スマホから送る」）→「使い始める」を押す
2. 出てきた QR を、スマホのカメラで読む。送信のページが開いて、パソコンとつながる
3. そのページを**ホーム画面に追加**しておく（iPhone は Safari の共有ボタン →「ホーム画面に追加」、Android はメニュー →「ホーム画面に追加」）

次から: スマホでアイコンを開く →「撮って送る」→ 撮る →「写真を使用」。パソコンでは Hazaism を開いておくだけです
（一度使い始めると、開くたびに自動で待ち受けます。上の帯の「スマホ」の点が緑なら待ち受け中です）。

- パソコンで作業の途中（輪郭を手で直した後や、敷き詰めた結果を DXF に保存する前）に届いたときは、
  消してよいかをパソコンの画面で確かめてから読み込みます。スマホには「確認待ち」と出ます。
- 写真はスマホからパソコンへ直接、暗号化して送られます。互いを見つけるためだけに、PeerJS の公開サーバー（0.peerjs.com）を
  使います（渡るのは接続用の番号と IP アドレスだけです）。直接つながらない回線では PeerJS の中継サーバーを通りますが、
  中身は暗号化されたままです。
- スマホとパソコンは**同じ Wi-Fi** につなぐのが確実です。どちらもインターネットにつながっている必要があります。
- Chrome の「省メモリ」でタブが眠ると受け取れません。設定 → パフォーマンス →「常にアクティブにするサイト」に
  `aho-wono.github.io` を追加してください。
- QR を知っている人は誰でも送れます。人に見られたときは「QR を作り直す」を押してください（前のスマホからは送れなくなります）。

撮影のコツ:

- **なるべく真上から**撮る。斜めでも補正しますが、真上に近いほど正確です（画面に傾きが出ます）。
- 板の**全体と、まわりの格子**が写るようにする。板が写真からはみ出すと、その部分は測れません（警告が出ます）。
- 板はマットに**ぴったり置く**。浮いていると、そのぶん寸法がずれます。
- 板の上や横に物を置かない（一緒に輪郭に入ってしまいます）。

### 2 輪郭

輪郭は直線と円弧でできています。

| 操作 | 働き |
|---|---|
| 頂点（丸）をドラッグ | 頂点を動かす。矢印キーで 0.1 mm ずつ（Shift で 1 mm） |
| 辺の中点（ひし形）をドラッグ | 直線 ⇄ 円弧 |
| 辺をダブルクリック | 頂点を追加 |
| 頂点を選んで Delete | 頂点を削除（前後が円弧なら 1 本の円弧にまとめる） |
| 矩形・傾いた矩形・円・3 点の円・楕円・多角形 | 「足す」「引く」で輪郭に足したり、切り欠いたりする |
| 測る | 2 点間の距離 |
| Ctrl+Z / Ctrl+Y | 元に戻す / やり直す |
| ホイール、右ドラッグ（または Space＋ドラッグ） | 拡大縮小、移動 |

- **板厚**を入れると、斜めから撮ったときに板の厚みで縁がずれて写るぶんを補正します（「検出し直す」で反映）。
- 写真に板が何枚か写っているときは、使う板を一覧か図の上で選べます。
- うまく検出できないときは「感度」を変えて検出し直すか、図形の道具で描いてください。

### 3 部材

- 1 ファイルが 1 つの部材です。線・円弧・円・ポリライン・楕円・スプラインを読みます（ブロックは展開します）。
- 寸法の単位は図面から読みます。外形寸法が実物と違うときは「単位」を直してください。
- **反転禁止**: 裏返して配置しません。レーザーの切り口は表と裏で幅が違うので、精度が要る部材に使います。
- 回転は「自由」「90° 刻み」「回転しない」から選べます。

### 4 敷き詰め

- **部材どうしの間隔**（初期値 0.5 mm）と**端材の縁からの余白**（初期値 1.5 mm）を守って配置します。
  輪郭は写真から測るので 0.5 mm 前後の誤差があります。写真の写りが悪いときは余白を大きめにしてください。
- 回転の刻みの初期値は 2°、計算時間の初期値は 10 秒です。刻みを細かくするほど、計算の準備に時間がかかります。
  一度変えた値はブラウザが覚えていて、次からはその値で始まります。
- 計算時間いっぱい、置き方を変えながら良い配置を探します。途中で止めても、その時点の最良の結果が使えます。
- 計算中と計算後に、次の数値が出ます。

| 数値 | 意味 |
|---|---|
| 経過時間 | 計算にかけた時間 |
| 試した置き方・1 秒あたり | 探した配置の数と速さ。パソコンの速さで変わる |
| 作業スレッド | 同時に計算している数（パソコンの CPU とメモリに合わせて 1〜4） |
| 利用率 | 端材の面積のうち、部材で使えた割合 |
| 置けた数 | 置けた個数 / 頼んだ個数 |
| 残りの最大のかたまり | 残った端材のうち、ひとかたまりで一番大きい部分の面積。次に使える大きさの目安 |
| 最小の間隔・最小の余白（実測） | できた配置を測った実際の値。設定以上になっていることを確かめられる |

  利用率の推移のグラフで、いつ頭打ちになったかが分かります。計算時間を決める目安にしてください。
- 入りきらなかった部材は一覧に出ます。

### 5 出力

- **原点**: 最初は、端材を囲む四角の**左上の角**です。「原点を角へ」で四隅を選べるほか、
  図の上をクリックして好きな点（頂点・角・辺に吸着）にもできます。
- **向き**: 「辺を X 軸に合わせる」で選んだ辺が X 軸と平行になります。±90°、180°、角度の数値入力もできます。
- **端材の輪郭**: 位置合わせの目安として、部材と違う色（初期値は青）の線で入ります。入れないこともできます。
- 部材は元の DXF の図形をそのまま（円弧は円弧のまま）移動・回転して書き出します。
- 「DXF を保存」を押すと、Chrome と Edge では保存する場所を選べます（次は前回の場所から開きます）。
- **写真に写した面を上にして**加工機に置いてください。裏返すと形が合いません。

#### SmartDIYs Cutter で使うとき

SmartDIYs Cutter は、DXF のレイヤーではなく**線の色ごと**にレイヤーを分けます。
端材の輪郭は部材と違う色で出力されるので、読み込んだあと「レイヤーパラメータ」を開き、
輪郭の色のレイヤーで **「加工なし」** にチェックを入れてください。輪郭は切られなくなります。
部材の線に輪郭と同じ色が使われていると、保存のときに知らせます。

## 精度の目安

- 格子の当てはめ誤差は 0.1〜0.2 mm 程度（画面に表示されます）。
- 輪郭は、縁がはっきり写っていれば 0.5 mm 前後です。影、ばり、マットの汚れ、板の浮きで悪くなります。
- 斜めから撮ったときは、板厚を入れると「板を大きく見積もらない」側に補正します。
  カメラ側の縁は、板の側面が写るぶん（最大で 板厚 × tan(傾き) 程度）小さめに出ることがあります。
- 大事な寸法は「測る」で確かめるか、実物をノギスで測って比べてください。

## 既知の制限

- 端材は 1 回に 1 枚です。
- マットの格子が擦れて消えている所は、板と区別がつきにくくなります（輪郭を手で直してください）。
- 板と同じくらいの大きさの物（工具など）が板に重なっていると、一緒に輪郭に入ります。
- DXF は R2010 形式で出力します。
- スマホでも開けますが、メモリが足りずに止まることがあります。パソコンで使ってください（スマホは「撮って送る」に使います）。
- 「スマホで撮って送る」は、PeerJS の公開サーバーが止まっていると使えません。そのときは写真をパソコンに移して読み込んでください。

## 開発者向け

レーザー用 PC で使うときに確かめることと、これまでに分かった注意点は
[docs/handoff-laser-pc.md](docs/handoff-laser-pc.md) にまとめてあります。

しくみ: 画面は HTML と JavaScript、計算は Python です。Python は [Pyodide](https://pyodide.org/)（ブラウザの中で動く Python）で、
利用者のブラウザの中で動きます。サーバーはなく、GitHub Pages は静的なファイルを配るだけです。

```
uv run python -m hazaism             # サイトを組み立てて手元で開く（http://127.0.0.1:8765/）
uv run pytest                          # 検査
uv run pytest tests/test_e2e.py        # 画面を通しで操作（初回は uv run playwright install chromium。ネット接続が要る）
uv run python tools/build_site.py      # 公開するサイトを site/ に組み立てる
uv run python tests/make_synthetic.py  # 正解つきの合成写真を作る
uv run python tools/make_icons.py      # アイコンを作り直す（hazaism/static/icons）
```

実物の写真を使う検査（`tests/test_e2e.py` と `test_vision.py` の一部）は、`tests/data/scrap_sample_01.png` に
写真を置いたときだけ走ります（この写真はリポジトリには入っていません）。

main に push すると、GitHub Actions が検査してからサイトを組み立てて GitHub Pages に置きます（`.github/workflows/pages.yml`）。
版を上げるときは `pyproject.toml` の `version` を変えます（画面の右上に出ます）。Pyodide の版は `hazaism/static/js/pyconfig.js` です。

```
hazaism/
  vision/             写真 → 輪郭（格子の検出、真上から見た画像への補正、板の切り出し、直線＋円弧への当てはめ）
  geom/outline.py     輪郭のモデル、図形を足す・引く
  dxfio/              部材 DXF の読込、結果の書き出し
  nest/               敷き詰め（raster.py: 置ける位置の計算、engine.py: 探索、verify.py: 検査と実測）
  jobs.py webapi.py   作業の状態と、画面からの頼みごとの入口
  static/             画面（HTML / CSS / JavaScript）
    js/backend.js       画面とブラウザ内の Python との橋渡し、敷き詰めの作業スレッドの指揮
    js/py-*-worker.js   Python を動かす作業スレッド（写真・DXF 用と、敷き詰め用）
    js/phone-link.js    スマホ → パソコンの写真の受け渡し（送り方の取り決め。両方で使う）
    js/phone-receive.js パソコン側の待ち受けと QR の画面
    send.html, js/send.js  スマホの送信ページ（Python は読まない軽いページ）
    js/vendor/          同梱したライブラリ（PeerJS 1.5.5、qrcode-generator 2.0.4。どちらも MIT）
    sw.js               読み込んだファイルをブラウザに残す（2 回目から速く開く）
tools/build_site.py   公開するサイトを組み立てる
tools/make_icons.py   アイコンを作る
```

しくみの要点:

- 板は反射で色が定まらないので、色ではなく「あるはずの格子線が見えない」ことを手がかりに板を見つけます。
- 敷き詰めは、端材と部材を細かい格子の画像にして「重ならずに置ける位置」をまとめて求め、
  置く順番と向きを変えながら繰り返します。作業スレッドを何本か立てて並列に探し、最後に元の図形で間隔と余白を検査します。
- スマホとパソコンは WebRTC（ブラウザどうしの直接通信）でつなぎます。パソコンは推測できない長さの番号で
  PeerJS のサーバーに待ち受けを登録し、QR でその番号をスマホに渡します。写真は 16 KiB ずつ、パソコンの返事を待ちながら送ります。
